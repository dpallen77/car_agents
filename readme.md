# Car Agents

This project is a small used-car analysis and AI agent prototype. It combines a synthetic car dataset with a buyer-side agent and a seller-side extraction/scoring flow.

## Overview

The repo is organized around a simple idea: load used-car listings, compare prices against market comps, and let an LLM-powered assistant reason over the data.

## File structure

- `hello.py` — minimal smoke test to confirm Python is working.
- `explore.py` — loads the CSV and prints the first rows, columns, and row count for quick data exploration.
- `cars_dataset.csv` — synthetic used-car listing dataset used by the project.
- `test_claude.py` — basic Anthropic API check to confirm the environment and API key are configured.
- `agent_log.txt` — runtime log of tool calls and responses generated by the agent.
- `car_buying/agent.py` — used-car shopping agent that orchestrates tool calls to search and evaluate listings.
- `car_buying/tools.py` — tool implementations for filtering, ranking, and comparing car listings against comparable vehicles.
- `car_selling/extract.py` — extracts structured data from free-form car listing text using Claude.
- `car_selling/score.py` — compares a listing price to comparable market values in the dataset.
- `car_selling/pipeline.py` — example end-to-end flow that extracts listing details and scores the deal.

## Main workflow

### Buyer-side flow

The buyer agent uses the tools in `car_buying/tools.py` to:

- search available listings
- filter by make, model, price, mileage, year, body type, condition, and accidents
- identify a shortlist of good-value deals
- score each candidate against comparable cars

The orchestration logic lives in `car_buying/agent.py`.

### Seller-side flow

The seller logic in `car_selling/extract.py` takes ad text and converts it into structured data such as:

- make
- model
- year
- mileage
- price
- title status
- accident history
- red flags
- summary

That extracted data is then passed into the price comparison logic in `car_selling/score.py`.

## Required setup

Before running the project, you must create a `.env` file in the repo root with your Anthropic API key:

```bash
ANTHROPIC_API_KEY=your_api_key_here
```

Example:

```bash
ANTHROPIC_API_KEY=sk-ant-api03-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

This key is required because the agent and extraction scripts call the Anthropic API in `car_buying/agent.py`, `car_selling/extract.py`, and `test_claude.py`.

## Data source

The project requires a CSV file named `cars_dataset.csv` in the repo root. The code expects the following columns:

- `listing_id`
- `make`
- `model`
- `model_year`
- `odometer_km`
- `listing_price`
- `listing_status`
- `body_type`
- `fuel_type`
- `country`
- `vehicle_condition`
- `accident_count`

Example CSV header:

```csv
listing_id,make,model,model_year,odometer_km,listing_price,listing_status,body_type,fuel_type,country,vehicle_condition,accident_count
```

The repo also uses these additional fields indirectly during analysis:

- `mileage` (derived from `odometer_km` in miles)

## Notes

- This repo is a prototype and uses synthetic practice data rather than real market pricing.
- The agent relies on Anthropic's API and expects an API key to be available via a `.env` file.
- The `.gitignore` file is set up to exclude secrets and generated artifacts.

## Typical usage

1. Activate the virtual environment.
2. Create a `.env` file with `ANTHROPIC_API_KEY`.
3. Make sure `cars_dataset.csv` exists with the required columns above.
4. Run scripts such as:
   - `python hello.py`
   - `python explore.py`
   - `python test_claude.py`
   - `python car_selling/pipeline.py`
   - `python car_buying/agent.py`

## Summary

This repo demonstrates a toy but realistic used-car decision workflow:

- parse listings
- compare them to market comps
- rank the best value deals
- let an LLM agent reason over the results
